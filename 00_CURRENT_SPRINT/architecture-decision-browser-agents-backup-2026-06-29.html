1. השאלה שהתחלנו ממנה

נדב בדק עם מישהו מבין בתחום אם אפשר לבנות צוות סוכנים שקורא/כותב לתיקיות מרקדאון, לומד מהניסיון, ומתעד פתרונות — הכל מתוך דפדפן. הטענה שנשמעה: "אין סיכוי", ובנפרד — חשש שמסמכים גדלים יעמיסו על הסוכנים.

תוצאת מחקר עומק (Claude Opus, Research+Web Search, 28.06.2026): שתי החששות נכונות חלקית. זה לא בלתי אפשרי — אבל יש מגבלה אמיתית של דפדפן שדורשת החלטת ארכיטקטורה.

2. הממצא המרכזי — File System Access API

היכולת של דפדפן לגשת/לכתוב לתיקייה מקומית של המשתמש (showDirectoryPicker) קיימת — אבל רק ב-Chromium (Chrome, Edge, Brave, Opera). לא Safari, לא Firefox, לא Mobile.

דפדפןגישה לתיקייה מקומיתנתח שוק (משוער 2026)
Chrome / Edge / Brave / Opera (Desktop)✅ כן (מ-Chrome 122+, persistent)~75-80%
Safari❌ לא (OPFS בלבד — סנדבוקס פרטי)~20-25%
Firefox❌ לא~2-3%
Mobile (Chrome/Safari ל-Android/iOS)❌ לא בכללכל המובייל
קהל המטרה של HypeShow = vibe coders / יזמים צעירים, חלקם בני נוער — קהל שבעיקרו Chrome-first. לכן PWA בלבד (בלי Tauri) מספיק לdesktop, אבל מובייל נשאר חסום מגישה ל"תיקייה שלי".

3. מה זה אומר על עלות/זיכרון (לא חסם, אלא מהונדס)

החשש השני (מסמכים שגדלים = עומס) נפתר בעזרת:

  • Memory tool של Anthropic — סוכן כותב/קורא זיכרון בקובץ, שולט מי שומר מה
  • Context editing + compaction — ניקוי אוטומטי של הקשר ישן (שיפור מדוד: עד 84% פחות טוקנים)
  • RAG — שליפה של ~4K טוקנים רלוונטיים בלבד, לא כל המאגר
  • Prompt caching — עד 90% הנחה על טקסט שחוזר על עצמו
תרחישעלות נאיבית/חודשעלות ממוטבת/חודש
לקוח בודד (40 שיחות 1:1 + 4 פגישות חברה + 8 פגישות קטנות)~$153~$22
מחיר הצעה: $149-249/חודש → מרווח גולמי 70-80%. כלכלית עובד אם בונים נכון — לא בארכיטקטורה נאיבית.

4. הסיכון האמיתי — לא טכני, אמינות סוכנים מרובים

Anthropic עצמה כותבת: מערכות multi-agent עם הקשר משותף ותלות גבוהה (בדיוק כמו "פגישת חברה" עם 9 קצינים) לא מתאימות היטב למצב הנוכחי של multi-agent systems.

סוג פגישהסטטוסהערה
1:1 (משתמש + קצין אחד)✅ בטוח, נבדק, עובדתבנית סטנדרטית
צוות קטן (3 סוכנים)✅ אפשריצריך speaker-orchestrator (מנהל תור דיבור)
פגישת חברה מלאה (9 סוכנים, transcript משותף)⚠️ בנוי אך שביר15× יותר טוקנים, 14 דפוסי כשל מתועדים, עלות גבוהה מאוד

speaker-orchestrator — מה זה בעברית

לא סאב-אייג'נטים. זה "מנהל ישיבה" — מחליט מי מדבר מתי, כדי שלא כל הסוכנים יענו בבת אחת (כאוס + עלות). זה feature הכרחי, אבל מוסיף חישוב (=כסף) ועיכוב לכל סבב.

החלטה מומלצת (סטיב): Stage 1 = סוכן בודד → Stage 2 = 3 סוכנים → Stage 3 = 9 סוכנים, רק אחרי שStage 2 עובר ללא תקלות.

6. אימות ותשלום — ההחלטה: OAuth

שלוש אופציות הוצגו והושוו. OAuth נבחר.

שיטהחיכוך למשתמשאבטחההתאמה לקהל (בני נוער / לא טכניים)סטטוס
API Keyגבוה — העתק-הדבקתקף לנצח אם נגנבנמוכהנדחה
OAuth (Login)נמוך — לחיצה אחתטוקן פג תוקף אוטומטיתגבוהה✅ נבחר
License Fileגבוה — קובץ + מיקוםקל לזיוף, קשה לבטלנמוכהנדחה

איך זה עובד בפועל

  1. משתמש מתקין HypeShow Extension ב-Claude Desktop / VSCode (פעם אחת)
  2. לוחץ "Login with HypeShow" → מאשר בדפדפן → מחובר
  3. כל שאלה שולחת בקשה ל-Vercel, מאומתת מול Supabase ("שילם? מורשה?")
  4. אם תקף → Vercel מריץ את הלוגיקה של הקצין הרלוונטי, מחזיר תשובה בלבד — הכללים/הvault נשארים בשרת, לא נחשפים
